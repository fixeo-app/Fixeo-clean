# Quartier SEO Pages — Retirement Decision

**Decision date:** 2026-09-10
**Decision owner:** Human approval (Q1 — Option A)
**Task:** Phase 1 Task 1.6 — Documentation only. `vercel.json` is NOT modified in this task.

---

## 1. Human Decision: Option A Approved

**All 111 current quartier SEO pages are retired from their public canonical URLs via permanent 301 redirects to the corresponding parent service × city page.**

This decision was confirmed during the FIXEO SEO V3 Phase 0 audit and Q&A process (Q1 — Option A).

Implementation of the redirects belongs to **Phase 3** only. This document defines the exact specification for that implementation.

---

## 2. Rationale

The 111 quartier pages were generated by `scripts/generate-pseo-v2.js` for three service families (plombier, électricité, serrurerie) across 6 cities and up to 8 quartiers per city. They are retired for the following reasons, all identified in the Phase 0 audit:

| Risk | Description |
|------|-------------|
| **Thin content** | Quartier pages are near-identical to their parent service × city pages, differing only in the neighbourhood keyword. No genuine neighbourhood-level product differentiation exists. |
| **Doorway page risk** | Multiple variants of the same core page with only localisation keyword substitution — a pattern Google's quality guidelines explicitly flag. |
| **Broken internal links** | Explorer cards on quartier pages use relative `href="plombier-casablanca.html"` paths. From `/plombier/casablanca/maarif`, these resolve to `/plombier/casablanca/plombier-casablanca.html` — a 404. |
| **Incorrect breadcrumb schemas** | BreadcrumbList JSON-LD references `/plombier-casablanca.html` (legacy flat file URL) instead of the canonical `/plombier/casablanca`. |
| **Sitemap orphan** | 111 pages are `index,follow` in their meta tags but absent from ALL sitemaps (`sitemap-lps.xml`, `sitemap-pseo.xml`). Googlebot discovers them only via crawl. |
| **Signal consolidation** | 301-redirecting to the parent service × city flagship page consolidates any link equity, crawl budget, and ranking signals accumulated by the quartier URLs. |

---

## 3. Current Route State (as of Phase 0 audit)

The following three rules exist in `vercel.json` inside the `"routes"` array (rewrite semantics — no redirect, no status code):

```json
{
  "src": "^/plombier/([a-z][a-z-]*)/([a-z][a-z-]*)$",
  "dest": "/quartier-plombier-$1-$2.html"
},
{
  "src": "^/electricien/([a-z][a-z-]*)/([a-z][a-z-]*)$",
  "dest": "/quartier-electricite-$1-$2.html"
},
{
  "src": "^/serrurier/([a-z][a-z-]*)/([a-z][a-z-]*)$",
  "dest": "/quartier-serrurerie-$1-$2.html"
}
```

**Key observations:**
- These are **rewrites** (no `status` field, no `headers.Location`). The public URL stays at the 3-segment path; the browser sees the HTML file content. No HTTP redirect is issued.
- The `electricien` pattern serves `quartier-electricite-$1-$2.html` (note: file prefix `electricite`, not `electricien`).
- The `serrurier` pattern serves `quartier-serrurerie-$1-$2.html` (file prefix `serrurerie`).
- All three rules appear **before** the 2-segment service × city rules in `vercel.json`. Routing order is preserved in the specification below.

---

## 4. Phase 3 Replacement Specification

The three rewrite rules must be **replaced in-place** (same position in the `routes` array) with the following permanent redirect rules:

```json
{
  "src": "^/plombier/([a-z][a-z-]*)/([a-z][a-z-]*)$",
  "headers": { "Location": "/plombier/$1" },
  "status": 301
},
{
  "src": "^/electricien/([a-z][a-z-]*)/([a-z][a-z-]*)$",
  "headers": { "Location": "/electricien/$1" },
  "status": 301
},
{
  "src": "^/serrurier/([a-z][a-z-]*)/([a-z][a-z-]*)$",
  "headers": { "Location": "/serrurier/$1" },
  "status": 301
}
```

These use the verified Vercel `routes` array syntax for this repository: `src` + `headers.Location` + `status: 301`. The `redirects` array syntax (with `destination`/`permanent`) is **not used** in this codebase.

---

## 5. Capture Group Mapping

| Group | Matches | Used in destination? |
|-------|---------|----------------------|
| `$1` | City slug (e.g. `casablanca`, `beni-mellal`) | **YES** — preserved in destination |
| `$2` | Quartier slug (e.g. `maarif`, `agdal`) | **NO** — intentionally discarded |

**The destination is always the 2-segment parent service × city URL.** The quartier slug is never forwarded.

### Redirect examples

| Source URL | Destination | Notes |
|------------|-------------|-------|
| `/plombier/casablanca/maarif` | `/plombier/casablanca` | `$1=casablanca`, `$2=maarif` (discarded) |
| `/plombier/casablanca/ain-diab` | `/plombier/casablanca` | Multi-word quartier handled by `[a-z][a-z-]*` |
| `/electricien/rabat/agdal` | `/electricien/rabat` | `$1=rabat`, `$2=agdal` (discarded) |
| `/electricien/marrakech/gueliz` | `/electricien/marrakech` | `$1=marrakech`, `$2=gueliz` (discarded) |
| `/serrurier/fes/ville-nouvelle` | `/serrurier/fes` | `$1=fes`, `$2=ville-nouvelle` (discarded) |
| `/serrurier/tanger/malabata` | `/serrurier/tanger` | `$1=tanger`, `$2=malabata` (discarded) |

All destination URLs match an existing 2-segment service × city page. No redirect chain is introduced: the destination URLs `/plombier/$1`, `/electricien/$1`, `/serrurier/$1` are handled by the **next** rule in the `routes` array (the 2-segment rewrite to the corresponding `.html` file).

**No redirect chain:** `3-segment → 301 → 2-segment` is one hop. The 2-segment rule is a transparent internal rewrite (no HTTP response to the client). The client receives exactly one 301.

The 111 existing `quartier-*.html` files in the repository root are **not deleted** during the redirect migration:

| File family | Count | Keep? |
|-------------|-------|-------|

| `quartier-serrurerie-*.html` | 37 | ✅ Retained as rollback asset |
| **Total** | **111** | **All retained** |

Once the redirect rules are in place, requests to 3-segment URLs are intercepted by the 301 rule **before** the rewrite rule would serve the HTML file. The files are unreachable via their public quartier URLs but remain available for rollback.

---

## 7. Sitemap Policy

- **Current state:** Quartier URLs are absent from all existing sitemaps (`sitemap-lps.xml`, `sitemap-pseo.xml`, `sitemap-blog.xml`).
- **V3 policy:** Quartier URLs must NOT be added to any V3 sitemap.
- **After Phase 3 implementation:** No sitemap action is needed — the URLs were never indexed via sitemap. Google may have crawled them directly; the 301 will update its index.

---

## 8. Canonical / Indexing Consequence

- Users and Googlebot reaching any 3-segment quartier URL receive a single **HTTP 301** to the parent 2-segment service × city URL.
- The parent service × city page has a correct `<link rel="canonical">` pointing to itself — no further redirect.
- **One hop, no chain:** `3-segment → (301) → 2-segment canonical`. ✅
- Any PageRank or link signals accumulated by the quartier URLs flow to the parent page.
- If Google has cached the quartier URLs as indexed pages, the 301 instructs deindexation over time.

---

## 9. Internal-Link Policy

V3 templates (Phase 2 generators) must never generate links to retired quartier URLs. Specifically:

- No `href="/plombier/{city}/{quartier}"` in any V3-generated page.
- No breadcrumb BreadcrumbList item pointing to a 3-segment quartier path.
- Explorer/artisan cards must link to the service × city parent (`/plombier/{city}`) or to individual artisan profiles, never to quartier pages.
- The V3 content-guard does not scan for these URLs (it governs text claims), so this constraint must be enforced at the template level.

---

## 10. Future Quartier Architecture

The quartier concept is **not permanently abandoned**. Future quartier pages may return only when all of the following conditions are met:

1. **Genuine content differentiation:** Neighbourhood-level content meaningfully differs from the parent service × city page (e.g. artisan density, local demand patterns, neighbourhood-specific context).
2. **Product support:** FIXEO's artisan matching meaningfully operates at neighbourhood granularity.
3. **Publishability criteria:** The combination passes the V3 publishability gate (artisan count ≥ `NEW_THRESHOLD`, city `publishable: true`, human approval).
4. **Explicit human approval:** A new quartier page family is never auto-generated — it requires a separate human decision to re-enable.

When future quartier pages are built, they will use V3 architecture: correct schema (`Organization + Service + BreadcrumbList`), static nav/footer, compliant vocabulary, and server-rendered artisan seed cards.

---

## 11. Rollback Procedure

To revert the Phase 3 redirect implementation:

1. In `vercel.json`, restore the three original rewrite rules (replacing the three 301 rules):
   ```json
   { "src": "^/plombier/([a-z][a-z-]*)/([a-z][a-z-]*)$", "dest": "/quartier-plombier-$1-$2.html" },
   { "src": "^/electricien/([a-z][a-z-]*)/([a-z][a-z-]*)$", "dest": "/quartier-electricite-$1-$2.html" },
   { "src": "^/serrurier/([a-z][a-z-]*)/([a-z][a-z-]*)$", "dest": "/quartier-serrurerie-$1-$2.html" }
   ```
2. Deploy. The 111 `quartier-*.html` files are already present — no restoration needed.
3. Verify that a 3-segment URL serves the quartier HTML content (not a redirect).

No file deletion is required at any point. The HTML files remain in the repository throughout.

## Appendix B — Regex Coverage Verification

Each regex covers the exact pattern produced by the legacy generator. Verified:

| Regex | Matches (examples) | Does NOT match |
|-------|-------------------|----------------|
| `^/plombier/([a-z][a-z-]*)/([a-z][a-z-]*)$` | `/plombier/casablanca/maarif`, `/plombier/beni-mellal/some-quartier` | `/plombier/casablanca` (2-seg), `/PLOMBIER/…` (uppercase — Vercel rewrites are case-sensitive) |
| `^/electricien/([a-z][a-z-]*)/([a-z][a-z-]*)$` | `/electricien/rabat/agdal`, `/electricien/marrakech/hay-riad` | `/electricien/rabat` (2-seg) |
| `^/serrurier/([a-z][a-z-]*)/([a-z][a-z-]*)$` | `/serrurier/fes/ville-nouvelle`, `/serrurier/tanger/val-fleuri` | `/serrurier/fes` (2-seg) |

The `[a-z][a-z-]*` pattern matches any lowercase slug (single word or hyphenated multi-word). It correctly handles city slugs like `beni-mellal` and quartier slugs like `val-fleuri`, `hay-mohammadi`, `sidi-maarouf`.
